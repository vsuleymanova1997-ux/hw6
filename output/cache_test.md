# Cache test: 12 practice documents, with and without cache

Numbers below are generated by `cache_test.py` from `output/cache_test.json` (one entry per model call).

## 1. Proof each setup did what it should

- Without cache: 0 of 24 calls read cached tokens (nothing was reused). **VALID**. The provider still wrote each unique prompt to its cache (259,045 write tokens, billed at the higher cache-write rate) and cannot be told not to, so see the pure no-cache line below.
- With cache: 20 of 23 calls after the very first reported at least 9,000 cached tokens (the handbook prefix). **VALID**. The very first call reported 0 cached tokens.
- Answers vs `practice_key.json` (6 fields x 12 docs = 72): with cache 62, without cache 64.

## 5. What surprised me, and why

1. **The without-cache setup still wrote to the cache.** It read 0 cached tokens, but the API reported 259,045 cache-write tokens, because the provider caches every prompt automatically and there is no switch to turn that off. Write tokens cost more than plain input, so this setup paid $0.006476 extra ($0.033793 instead of $0.027317). A random first line stops reuse, not writing.
2. **Caching is not guaranteed even with an identical prefix.** 3 of 23 later with-cache calls missed (p01_bluehen_quote.html call 2, p02_elmcity_quote.html call 1, p08_chapelst_email.eml call 2); the very first call is a cold start. Cache hits are best effort and depend on routing and timing.
3. **Savings are 72.5%, not the 85.2% that Problem 2's handbook-only math predicts.** The cache-write call and the misses still pay write prices, and the document text and output tokens are never cached.
4. **Second calls in a run read slightly more from cache than first calls** (about 10,690 vs 10,658 tokens): the run's own first request already wrote the user message and the tool call, which the second request reuses.
5. **Real input is bigger than the estimate.** The first call was 10,834 tokens against 10,058 for the handbook alone: instructions, tool definitions and the document come on top, and tiktoken is only an estimate of this model's tokenizer.
6. **Accuracy is 62/72 with cache and 64/72 without.** That gap is not caching: this is the plain agent with no defenses, and it is fooled by the trap documents (hidden prices and lead times, a swapped vendor). Caching does not change the answers.
